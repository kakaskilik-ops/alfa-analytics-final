## Запуск

Node.js 22.12+ (22/24 LTS), npm. Для серверных тестов нужен Deno 2. Для полноценного окружения Supabase — его CLI и Docker.

```bash
npm ci
cp .env.example .env
npm run dev
npm run test
npm run lint
npm run build
npm run test:db
npm run test:server
npx playwright install chromium
npm run test:browser
```

В Linux можно использовать уже установленный Chromium: `CHROMIUM_PATH=/usr/bin/chromium npm run test:browser`. Браузерные тесты сами запускают два Vite-сервера на 5182/5183, работают без реальных ключей и без обращения к production. `test:db` использует изолированный PGlite и тестовые интерфейсы Auth/Vault/cron; он не заменяет проверку расширений в локальном Supabase.

`build` включает TypeScript приложения и Vite. В `dist/` появляется статическая сборка. Сборка, зависимости, `.env`, архивы, ключи и результаты браузерных тестов исключены из git.

## Что работает в коде

- Главная, каталог, аналитика, новости и чат ИИ. Реестр источников доступен отдельным пунктом меню.
- Независимые рынки Европы, США и Азии, выбор спецификации, отдельная история и страна происхождения азиатского наблюдения.
- Режимы USD/кг, USD/т, EUR/кг, RUB/кг, CNY/кг. Пересчёт только по подтверждённому курсу с собственными датой и источником пары. Без курса цены не подставляются.
- Сравнение регионов, динамика, графики, CSV/Excel, последние новости в карточках, метки реальных публикаций и список событий в аналитике.
- RSS/Atom/JSON Feed: проверка размера и XML, защита от DTD, очистка разметки, классификация по 13 материалам/регионам/темам, канонизация URL и дедупликация.
- Серверные ИИ-чат, анализ новости, ежедневный и еженедельный обзор. Подтверждённые данные загружаются самим сервером, история чата ограничена, ключ остаётся на сервере. Есть квота пользователя, общий дневной лимит токенов и кеш обзоров.

**Лицензированных региональных котировок и ключа бесплатного ИИ пока нет. Серверные сборщики и расписания развёрнуты в подтверждённом проекте.** Без них отображаются состояния отсутствия данных/настройки. В коде нет демонстрационных production-цен или имитации ответов ИИ. Текущие результаты и ограничения: [docs/REPORT.md](docs/REPORT.md), источники и условия: [docs/SOURCES.md](docs/SOURCES.md).

## Supabase и миграции

1. Начните со staging или локального Supabase: `supabase start`, затем `supabase db reset` **только локально**. Проверяйте историю существующей БД перед любым применением.
2. Первые 7 миграций сохранены. Новая `20261112180000_regional_markets_and_news.sql` добавляет активный каталог из 13 ID, рынки, коммерческие поля, новости, журналы, кеш и лимит ИИ. Старые 129 материалов не удаляются; добавляется отсутствовавший хром. Прежние строки без коммерческих условий остаются в БД, но не становятся региональными котировками автоматически.
3. Перед изменением удалённой БД сделайте резервную копию, проверьте план миграции и получите разрешение. Удалённая БД в этой работе не менялась.
4. В браузерном `.env`: только `VITE_SUPABASE_URL` и публичный `VITE_SUPABASE_ANON_KEY`. Все `VITE_*` видны посетителю. Service role и ключ OpenAI здесь запрещены.
5. Разверните Edge Functions после проверки: `ai-analyze`, `collect-news`, `ingest-quotes`, `ingest-regional-history`, `collect-market-data`. Их entrypoint-файлы запускают Deno.serve, обработчики вынесены отдельно для тестирования.
6. Настройте Auth/SMTP, URL входа и разрешённые redirect URL домена. ИИ требует пользовательскую сессию.

RLS закрывает запись от посетителей и внутренние настройки/журналы/бюджет. Новости и котировки публикуются только в разрешённой области. Исторические записи без региона не используются как региональная история.

## Подключение цен и истории

Контракт и endpoint: [docs/API.md](docs/API.md). Источник должен передавать реальную спецификацию: форму, марку, состав, чистоту или содержание основного элемента, условия поставки, рынок, регион и страну для Азии. Неизвестные значения нельзя выводить из названия металла.

`QuoteProvider` и `CanonicalJsonProvider` позволяют подключать согласованный серверный JSON-шлюз поставщика. Это не реализация закрытых API LME/CME/SHFE. Для каждого требуется договор, разрешение на распространение и mapping по документации предоставленного продукта. Проверка официальных условий: [docs/SOURCES.md](docs/SOURCES.md).

Новый `collect-fx` использует Frankfurter v2 для USD/EUR/RUB/CNY, сохраняет исходный ответ и датированные кросс-курсы. API и парсер проверены реальным запросом; удалённое сохранение 84 курсов проверено. Исходный сборщик сохранён, но новое расписание его не использует. Старый Yahoo-адаптер не имеет достаточных коммерческих спецификаций; `ENABLE_YAHOO_UNOFFICIAL` должен оставаться `false`, иначе endpoint возвращает явную ошибку совместимости. Он не создаёт цены трёх регионов из одного фьючерса.

## Подключение новостей

1. В новой миграции зарегистрирована официальная RSS USGS Mineral Resources. Для добавления источника оператор заполняет `news_sources`: HTTPS feed URL, формат rss/atom/json, разрешённые домены, ссылку и примечание по лицензии, частоту, `approved_at`, `enabled`.
2. Публичность URL сама по себе не означает право на перепубликацию. Используются только одобренные метаданные; полные статьи и изображения не загружаются. Для новых издателей проверьте условия отдельно.
3. `collect-news` вызывается доверенным сервером с `x-collector-token` из Supabase Vault. Тот же секрет используется существующим сборщиком. Он не должен попадать в браузер или git.
4. Для нового общего расписания используйте `ops/activate-automation.sql` по инструкции в docs/DEPLOYMENT.md. Старый отдельный вариант `ops/news-schedule.sql` не включайте одновременно. По умолчанию — каждые 30 минут; выражение cron можно изменить. В подтверждённом облачном проекте общее расписание **активно**.
5. Частота контролируется атомарной SQL-функцией. Есть ETag/Last-Modified, ограниченные повторные попытки, лимит размера, allowlist редиректов, журнал запусков и защита от повторного импорта.
6. Англоязычные публикации без перевода показывают русский статус и оригинальный заголовок. Для автоматического перевода настройте серверный OpenAI и `NEWS_AI_TRANSLATION=true`. Переводится не более одной публикации за запуск; ранее импортированные pending/failed тоже обрабатываются. Ошибки не заменяются выдуманными резюме.

## ИИ и контроль расходов

Серверные secrets (не браузер): `OPENROUTER_API_KEY`, необязательные `OPENROUTER_MODEL`, `GROQ_API_KEY`, `GROQ_FREE_TIER_CONFIRMED`. Legacy OpenAI требует явных `AI_PROVIDER=openai` и `ALLOW_PAID_AI=true`; по умолчанию платный маршрут выключен. Пример — `supabase/.env.example`.

`AI_DAILY_TOKEN_LIMIT=0` по умолчанию блокирует платные вызовы. После вашего решения включить API задайте положительный лимит, например 100000. База жёстко ограничивает лимит сверху 1 000 000 токенов/сутки UTC. Перед анализом резервируются 16000 токенов, перед переводом 8000; неиспользованный резерв не возвращается. Это консервативный операционный лимит, не долларовый биллинг. Дополнительно настройте бюджет проекта OpenAI и выберите модель осознанно.

Пользовательская квота — 10 запросов в час. Контекст и переписка ограничены, провайдер имеет timeout 45 секунд, клиент — 90 секунд. Обзоры и анализ новости кешируются на час отдельно для пользователя. ИИ обязан отделять факты от гипотез и не объявлять совпадение новости с ценой доказанной причинностью. Без реальных данных, ключа или бюджета возвращается явное состояние, а не искусственный ответ.

**Платные вызовы в ходе разработки не выполнялись.** Серверные тесты заменяют модель и внешние ответы тестовыми.

## VPS и домен

Сохранена схема статического frontend + Supabase Edge Functions. На VPS установите Node LTS и Caddy, выполните `npm ci`, настройте публичный `.env`, запустите проверки и `npm run build`, скопируйте `dist/` в `/var/www/alfa-analytics`. В `ops/Caddyfile` замените домен, настройте DNS A/AAAA на IP сервера и откройте 80/443. Проверьте Caddyfile перед перезагрузкой; Caddy выпустит TLS. Для своего API-домена дополните CSP.

Отдельно настройте Supabase Auth redirects, `ALLOWED_ORIGIN`, секреты, Edge Functions, источники и расписание; проверьте импорт, RLS, новости, FX и ИИ на staging. Настройте резервные копии, мониторинг и предыдущую сборку для отката. Ни push, ни развёртывание, ни удалённые миграции на этом этапе не выполнялись.

Архитектура: `src/` — интерфейс и клиентские сервисы, `shared/news.ts` — общий парсер/классификатор, `supabase/functions/_shared/` — контракты, сеть и ИИ, `supabase/migrations/` — БД, `tests/browser/` — браузерные проверки, `scripts/test-database.mjs` — изолированная проверка SQL.

Методика — [docs/METHODOLOGY.md](docs/METHODOLOGY.md), текущий отчёт — [docs/REPORT.md](docs/REPORT.md), старый этап — [docs/STAGE1-REPORT.md](docs/STAGE1-REPORT.md). `node scripts/generate-catalog.mjs` теперь пишет `ops/catalog-upsert.sql`, не переписывает применённую миграцию.

## Автоматизация и хостинг

`npm run deploy:plan` готовит игнорируемый пакет SQL и Edge-функций без изменения облака. `npm run deploy:supabase` предлагает проверяемый CLI dry-run. Общий алгоритм аналитики используется в браузере и серверной функции; новости, FX, котировки и ориентиры имеют отдельные расписания. GitHub Actions проверяет код без production-ключей и без автоматического deploy. Cloudflare Pages: build `npm ci && npm run build`, output `dist`, Node 24; публичные настройки Supabase задаются в Pages. DNS не меняется.
