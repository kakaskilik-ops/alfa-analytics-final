# ALFA ANALYTICS

Аналитическая платформа рынка металлов на React 18, TypeScript, Vite, Tailwind CSS, Recharts и Supabase. Доработана предоставленная версия; интерфейс и исходный каталог сохранены. Цены и графики не генерируются. Без настроенной базы каталог работает, рыночные показатели показывают отсутствие данных.

## Установка и проверка

Нужен Node.js 22.12+ (ветки 22 или 24 LTS) и npm.

```bash
npm ci
cp .env.example .env
npm run dev
npm run test
npm run lint
npm run build
npm run preview
```

`build` включает строгую проверку TypeScript приложения и конфигурации Vite. `dist/` — статическая production-сборка. `npm run preview` предназначен для локальной проверки. В `.env` допустимы только публичные URL и anon/publishable key Supabase. Любая переменная `VITE_*` попадает в браузер. Секреты service role, OpenAI и поставщиков — только на сервере.

## Архитектура

- `src/data/`: каталог из 129 материалов, 9 категорий, реестр источников. Каталог доступен без БД; SQL-копия генерируется из него командой `node scripts/generate-catalog.mjs`.
- `src/types/market.ts`: типы материалов, наблюдений, источников и результатов. Отсутствующая рыночная метрика — `null`.
- `src/services/database.ts`: единая точка чтения Supabase, проверка структуры ответа, ограничение объёма выборок. Браузер не записывает котировки.
- `quoteValidation.ts`, `averagePrice.ts`: проверка и расчёт сопоставимых цен, независимость источников, свежесть и выбросы.
- `liveData.ts`: актуальные котировки и история, кеш 5 минут, отсечение устаревших данных. Не создаёт недостающую историю.
- `market.ts`: индекс по общим датам, динамика, волатильность. Совместимые старые имена `buildQuote`/`buildHybridQuote` сохранены без генерации цен.
- `currency.ts`: только подтверждённые курсы, выбор самого нового значения пары, отсутствие курса не заменяется демонстрационным.
- `src/pages/`: обзор, каталог, аналитика, источники, ИИ. Страницы загружаются по требованию; навигация сохраняется в URL hash.
- `supabase/functions/`: защищённый сборщик, серверный импорт котировок и ИИ. Реальные платные API в ходе разработки не вызывались.
- `supabase/migrations/`: выбранная последняя последовательность исходных миграций и новые дополнительные миграции.

## Подключение Supabase

1. Создать отдельный проект или локальный Supabase для проверки. Перед изменением существующей базы сделать резервную копию и сверить историю миграций.
2. В браузерном `.env` задать `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` (anon или публичный publishable key, никогда service role).
3. Проверить миграции локально через Supabase CLI: `supabase start`, `supabase db reset`. Расширения `pg_cron`, `pg_net`, Vault требуются для проверки токена и будущего расписания. Здесь они не запускались в реальном Supabase.
4. После проверки вручную связать CLI с выбранным проектом и применить миграции. **Удалённые миграции в ходе этой работы не применялись.** Если в проекте уже другая история, сначала подготовить миграцию перехода; не выполнять `db reset` для удалённой базы.
5. Настроить серверные secrets по `supabase/.env.example`. URL и service role в Edge runtime предоставляет Supabase.
6. Развернуть `collect-market-data`, `ingest-quotes`, `ai-analyze`. Сборщик и импорт проверяют токен Vault; у них gateway JWT выключен намеренно. ИИ проверяет JWT и пользователя самостоятельно, а также использует gateway JWT.
7. Для входа ИИ настроить Supabase Auth, разрешённые redirect URL своего домена и почтового провайдера. Кнопка входа отправляет ссылку только по запросу пользователя. Доступность OpenAI проверяется сервером при запросе.
8. Для расписания вручную создать Vault secret `collector_url` со своим адресом функции и выполнить `ops/schedule.sql` один раз. Миграция генерирует `collector_token`. Не копировать секрет в браузер, git или публичные журналы. Исходный жёстко заданный адрес старого проекта удалён.

Публичные пользователи читают только разрешённые данные. Для записей котировок, курсов и расчётов нужен service role. Внутренние сообщения поставщиков закрыты; журнал показывает только статус и счётчики. Избранное в интерфейсе хранится локально; исходная таблица favorites и её политики сохранены.

## Источники и API

Подробности: [docs/API.md](docs/API.md), методика: [docs/METHODOLOGY.md](docs/METHODOLOGY.md).

- Frankfurter / ЕЦБ: реализован серверный сбор USD → EUR, GBP, CNY, SEK. RUB исключён из этого запроса: наличие актуального курса нельзя предполагать. Для RUB нужен отдельный подтверждённый поставщик.
- Yahoo: исходный адаптер сохранён, исправлен и выключен по умолчанию (`ENABLE_YAHOO_UNOFFICIAL=false`). Перед включением требуется проверить условия использования. Это непрерывные фьючерсные ряды, не цены наличного металла. HRC исключён из адаптера из-за короткой тонны вместо метрической.
- LME, CME/COMEX, SHFE, LBMA: нужны договоры, разрешения на распространение и адаптеры к конкретным предоставленным API. Здесь нет неподтверждённых «готовых» интеграций с закрытыми API.
- Редкие металлы, марки и лом: нужны проверенные региональные поставщики, спецификации и условия поставки. При неоднозначной марке состав требует сертификата, он не выдумывается.
- OpenAI: серверный `OPENAI_API_KEY` и `OPENAI_MODEL`. Endpoint использует реальные строки БД, игнорирует присланные клиентом цены, указывает период и источники. Ограничение — 10 запросов пользователя в час, атомарно в БД. ИИ не заменяет проверку человеком; объяснение причин без новостных данных не обещается.

## VPS и домен

1. На сервере установить Node.js LTS 22/24 и Caddy. Создать отдельного пользователя развёртывания.
2. Скопировать исходники, выполнить `npm ci`, настроить публичный `.env`, затем `npm run test && npm run lint && npm run build`.
3. Скопировать содержимое `dist/` в `/var/www/alfa-analytics` с правами чтения для Caddy.
4. Создать DNS A/AAAA домена на IP сервера. Открыть входящие 80/443.
5. Заменить домен в `ops/Caddyfile`, проверить `caddy validate --config /etc/caddy/Caddyfile` и перезагрузить Caddy. Он выдаёт TLS-сертификат автоматически. Если Supabase self-hosted или свой домен API, дополнить CSP точным разрешённым API-доменом.
6. В Supabase задать домен Auth redirects и `ALLOWED_ORIGIN`; развернуть функции и настроить источники. Браузер обращается к Supabase, VPS обслуживает статические файлы.
7. Проверить вход, RLS, права на данные, реальный импорт, свежесть, валюты и восстановление после сбоя на staging. Настроить резервные копии Supabase, мониторинг Edge Functions и ротацию секретов. Для отката хранить предыдущую сборку и резервную копию БД.

Публикация, настройка домена, удалённая БД, платные запросы и git push в ходе разработки не выполнялись.

## Проверки и ограничения

См. [docs/REPORT.md](docs/REPORT.md). Тесты используют явно тестовые фикстуры; в production они не импортируются. Без подключённых источников графики намеренно пусты. Реальное получение данных, SMTP, расширения Supabase, TLS и DNS проверяются после подключения инфраструктуры. Размер библиотеки графиков остаётся заметным; она вынесена в отдельный кешируемый пакет.
