# Серверные интеграции

Все источники должны быть зарегистрированы в data_sources, материалы — в metals. Статус «Ожидает настройки» не означает работающее подключение. Не храните ключи в api_endpoint, URL, last_error или браузерном коде.

## Импорт проверенным сервером

`POST /functions/v1/ingest-quotes`, заголовок `x-collector-token`: значение серверного Vault collector_token. Максимум 100 записей и 256 КиБ за запрос. Токен подходит только для доверенной серверной системы. Никаких CORS-разрешений для браузера нет. Пакет проверяется целиком; при некорректной записи возвращается 400 без записи пакета. Повторные наблюдения той же спецификации обновляются по уникальному ключу. Дубли внутри одного пакета отклоняются.

Контракт: `supabase/functions/_shared/providers.ts`. Адаптер реализует QuoteProvider, получает исходный payload с timeout/abort, проверяет его и формирует ProviderQuote[]. Не доверяйте единице, валюте, часовому поясу или химическому составу по одному названию тикера. Параметры из браузера не должны задавать URL поставщика или API-ключ.

Тело — массив объектов со следующими полями (пример структуры, **не реальные котировки**):

```json
[{
  "metalId": "copper", "sourceId": "your-registered-source",
  "price": 10, "currency": "USD", "unit": "kg",
  "region": "Россия", "marketType": "wholesale", "priceType": "assessment",
  "grade": "М1", "productForm": "Катод", "composition": null,
  "publishedAt": "2026-11-12T10:00:00Z", "retrievedAt": "2026-11-12T10:01:00Z",
  "sourceUrl": "https://your-source.example/quote"
}]
```

Пример нельзя использовать как production-данные. Адаптер принимает только USD: для других валют сначала требуется серверная конвертация по подтверждённому курсу с сохранением исходной валюты и аудита. Клиентские функции конвертации не заменяют такой серверный аудит. В БД исходные валютные поля предусмотрены. Качество берётся из серверного реестра, не из присланного пакета. Для поставщиков с общим первоисточником назначьте одинаковый independence_id.

История не достраивается из текущей цены. Загружайте только полученные от поставщика исторические наблюдения доверенной серверной логикой в price_history, с USD/кг и comparison_key в точном формате JSON.stringify([metalId,'USD','kg',region,marketType,grade,productForm,composition,priceType]). Требуются положительные OHLC, правильные даты и собственная проверка лицензии. Общий endpoint импорта исторических файлов пока не реализован.

Коды: 401 — неверный токен, 400 — неверный пакет/неизвестный источник, 413 — превышение объёма, 503 — недоступная инфраструктура. Ошибки не раскрывают SQL, ключи и ответы поставщиков.

## Исходный сборщик

`POST /functions/v1/collect-market-data` с тем же серверным токеном. Реализованы Frankfurter и опциональный неофициальный Yahoo. У запросов timeout 15 секунд. Для Yahoo проверяется валюта, реальное время публикации, цена и OHLC; история нормализуется в USD/кг и получает ключ спецификации. Несовпадение валюты не маскируется как USD. Старый HRC mapping выключен из-за короткой тонны. Не включайте неофициальный адаптер до проверки условий источника.

## ИИ

`POST /functions/v1/ai-analyze` с пользовательским Supabase Bearer JWT. Тело: `{question, metalIds?: string[], period:'1D'|'1W'|'1M'|'3M'|'6M'|'1Y'|'5Y'}`. До четырёх материалов, вопрос 3–2000 символов. Поле context не используется. Endpoint сам загружает каталог, подтверждённые свежие котировки и историю за период. Указывает периоды и источники, отличает факт от гипотезы. Без истории вывод о тренде не обещается. Лимит 10 обращений пользователя за календарный час; повторные ошибки также занимают квоту.

Только серверные secrets: OPENAI_API_KEY, OPENAI_MODEL, ALLOWED_ORIGIN. Без ключа — 503. Без подходящих данных — сообщение о недостатке данных, модель не вызывается. 401 — нужен вход, 429 — квота исчерпана, 400 — неверный ввод. Запрос к OpenAI имеет timeout 45 секунд. В ходе разработки обращения к платной модели не выполнялись.

До production рекомендуется добавить глобальный бюджет OpenAI, операционный мониторинг и политику доступа к ИИ в соответствии с моделью пользователей. Текущая реализация даёт базовое ограничение, не биллинг и не защиту от массовой регистрации.
