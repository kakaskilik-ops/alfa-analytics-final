# API этапа 2

Все endpoint работают через Supabase Edge Functions. Browser использует только публичный Supabase key и пользовательский JWT. Service role, collector_token и OpenAI key остаются на сервере. Источники — зарегистрированные data_sources, материалы — 13 ID из active_metals. Старые данные не удаляются.

## Котировки

`POST /functions/v1/ingest-quotes`, `x-collector-token`: серверный Vault token. До 100 записей и 256 КиБ. Общий контракт — `_shared/providers.ts`; HTTPS JSON-транспорт — `_shared/quoteAdapters.ts`. Адаптер конкретного поставщика обязан проверить права, формат, валюту, единицу и коммерческие условия до импорта. CanonicalJsonProvider не является готовым адаптером закрытых LME/CME/SHFE.

Структура одной записи (ниже **тестовая структура, не реальная котировка**):

```json
{
  "metalId": "tungsten", "sourceId": "your-registered-source",
  "price": 100, "currency": "USD", "unit": "kg",
  "region": "Азия", "country": "Китай", "purity": 99.9,
  "elementContent": null, "deliveryTerms": "FCA согласованный склад",
  "grade": "Согласованная марка", "productForm": "Порошок",
  "composition": null, "marketType": "spot", "priceType": "assessment",
  "publishedAt": "2026-11-12T10:00:00Z", "retrievedAt": "2026-11-12T10:01:00Z",
  "sourceUrl": "https://your-source.example/quote"
}
```

Тело endpoint — массив записей. Поддерживаются kg/ton/g/ozt/lb, входная валюта USD. Для прочих исходных валют нужен серверный mapping по подтверждённому курсу с аудитом исходного значения; текущий адаптер не подставляет FX самостоятельно. Pure metal, scrap, raw и alloy — разные marketType; формы и составы не объединяются.

Обязательны: активный материал, один из трёх регионов, марка, форма, условия поставки, чистота или содержание основного элемента в (0,100], страна для Азии, положительная конечная цена, корректные даты и HTTPS-ссылка. Свежесть текущей котировки — 4 суток. Сервер берёт quality_score из реестра, а не доверяет присланному весу. Перепечатки поставщика объединяются серверным independence_id.

Уникальность наблюдения включает материал, источник, время, регион, рынок, марку, форму, состав, тип цены, страну, чистоту, содержание элемента и условия поставки. Различные спецификации в одну цену не сливаются.

## История

`POST /functions/v1/ingest-regional-history`, тот же серверный token, до 100 записей/256 КиБ. Запись включает все поля ProviderQuote плюс `tradeDate: YYYY-MM-DD`, `open`, `high`, `low`, `close` в исходной единице. Поля price и publishedAt отражают реальное наблюдение поставщика; retrievedAt — фактическое получение. История до 1826 суток, без будущих дат, с проверкой OHLC. Масса нормализуется в USD/кг.

`comparison_key` создаётся сервером одинаково с frontend: JSON.stringify([metalId,'USD','kg',region,marketType,grade,productForm,composition,priceType,country,purity,elementContent,deliveryTerms]). Отдельно записываются region_code и country. Браузер запрашивает историю конкретного источника и ключа. История не генерируется и не масштабируется под текущую цену.

## Новости

`POST /functions/v1/collect-news`, серверный collector token. Тело не задаёт URL: адреса и разрешённые домены берутся только из одобренного news_sources. Удалённые редиректы за пределы allowlist запрещены. Размер ленты ≤1 МиБ, до 100 элементов, DTD/ENTITY отклоняются. Поддерживаются RSS, Atom, JSON Feed; не загружаются страницы полных статей.

Обрабатываются только публикации с именем нужного металла и промышленным/экономическим контекстом. Голые W/Co/Sn и случайные названия не служат достаточным основанием. Регион определяется текстом публикации, а не расположением источника; если доказательств нет, регион не определён. Категории: добыча, производство, торговля, санкции, логистика, спрос, предложение, технологии, регулирование. Классификация эвристическая и может пропустить релевантный материал.

Удаляются tracking-параметры URL; БД обеспечивает уникальность canonical_url и fingerprint нормализованного заголовка/дня. Это не семантический поиск всех перепечаток с изменённым заголовком. Логи и частота хранятся сервером, токены в логах отсутствуют. Дата публикации не заменяется датой загрузки.

Запросы используют ETag/Last-Modified, timeout 15 секунд, максимум один повтор при 429/5xx с коротким Retry-After. Длинный Retry-After откладывается на следующий запуск. Для соблюдения бюджета времени обрабатывается до трёх источников за запуск; при незавершённом обходе ETag не продвигается. Перевод — максимум одна queued-публикация за запуск и только при включённом NEWS_AI_TRANSLATION, ключе и бюджете.

## ИИ

`POST /functions/v1/ai-analyze`, Bearer JWT вошедшего пользователя. Тело:

```json
{"question":"Сравни стоимость вольфрама в Европе и Азии","metalIds":["tungsten"],"period":"1M","kind":"chat","messages":[]}
```

`kind`: chat/news/daily/weekly. Для news передаётся newsId — UUID из БД. Region опционально один из Европа/США/Азия. До 13 материалов, 10 предыдущих сообщений по 2000 символов; контекст фактически дополнительно ограничен. Period: 1D/1W/1M/3M/6M/1Y/5Y. Вопрос 3–2000 символов. Клиентские цены/context не используются.

Сервер загружает только активный каталог, подтверждённые свежие коммерческие котировки, региональную историю и разрешённые новости. Проценты региональных оценок рассчитываются детерминированно по одинаковым условиям и минимум двум независимым источникам в каждом регионе. Текст модели обязан различать наблюдения, гипотезы и неопределённость. Метаданных RSS недостаточно, чтобы утверждать чтение полной статьи или причинную связь события с ценой.

Квота пользователя 10/час; общий бюджет токенов резервируется атомарно в БД. Без ключа — 503 с описанием настройки, без бюджета — 429, при нехватке данных — честное сообщение без обращения к модели. Недопустимые параметры — 400, отсутствие входа — 401, новость не найдена — 404. У поставщика timeout 45 секунд, browser имеет отдельный timeout 90 секунд. Обзоры и анализ новости кешируются на час для конкретного пользователя.

Ни один платный вызов во время разработки не выполнялся. Проверки обработчика используют тестовый fetch-провайдер, а не реальный API.
