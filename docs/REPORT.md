## ИИ — реализован, реальный ответ пока не проверен

Основной бесплатный провайдер OpenRouter, `google/gemma-4-31b-it:free`; резерв `openrouter/free`, необязательный Groq. Исследованы официальные API/лимиты OpenRouter, Groq и Gemini; выбор и ссылки в SOURCES.md. Бесплатные маршруты защищены нулевой ценой в запросе; платный legacy OpenAI сохранён только как явно включаемая владельцем возможность. Биллинг не подключался.

Реализованы русский чат, выбор одного/нескольких материалов, период и регион, вопросы-шаблоны, подробное заключение, анализ всех материалов, кнопка «Обновить анализ», карточка последнего автоотчёта, ссылки на источники, вход через Supabase Auth. Данные и новости читает сам сервер; клиентские контекстные числа не считаются доказательством. Сведения производства/запасов не выдумываются при отсутствии рядов.

Модель возвращает качественный JSON и выбирает ID серверных фактов; числа, даты и ссылки вставляет сервер из проверенного набора. Выдуманные ID, числовой прогноз или URL в свободном тексте отклоняются. Причинные интерпретации и условные сценарии отделены от фактов; эта проверка формата **не является доказательством безошибочности всех рассуждений модели**. Нужна проверка настоящих ответов после подключения ключа.

JWT проверяется внутри функции через Auth. Есть пользовательская квота, атомарный общий бюджет попыток/токенов, ограничение в минуту, блокировка одинаковой работы, кеш по данным/запросу, максимум два автоотчёта в сутки и остановка при недоступности API. Все ключи только в Supabase Secrets. Приложение продолжает работать без ИИ.

Фактические проверки: `GET ai-status` → HTTP 200, `configured=false`, `verifiedAt=null`; защищённый запуск отчёта → `partial / ai_not_configured`; неавторизованный чат → 401. **Успешного настоящего запроса к модели нет.** Тесты провайдера используют mocks, не имитируют production-ответы.

## Минимальные действия владельца

1. Зарегистрировать допустимый по стране аккаунта бесплатный OpenRouter, без пополнения и платной подписки. Создать ключ на [странице API Keys](https://openrouter.ai/settings/keys). В [Supabase Secrets этого проекта](https://supabase.com/dashboard/project/vlfzjvwgrvyllvshwmzr/functions/secrets) добавить **OPENROUTER_API_KEY**. Не отправлять ключ в чат, GitHub или VITE_*. Переустанавливать приложение не требуется: модель по умолчанию уже задана в функции. Необязательный Groq требует отдельного ключа и подтверждения бесплатного тарифа.
2. В GitHub репозитории → Settings → Secrets and variables → Actions добавить **VITE_SUPABASE_ANON_KEY** с публичным publishable/anon key из Supabase → Settings → API Keys. Это публичный клиентский ключ, не service-role. VITE_SUPABASE_URL уже имеет правильное значение по умолчанию в workflow; можно задать repository variable. Cloudflare secrets не изменялись.
3. После ключа: проверить ai-status, войти собственным аккаунтом на разрешённом URL Supabase Auth, выполнить вопрос по металлу и сверить факты/ссылки ответа. Это обязательный шаг до объявления ИИ рабочим. Cron попробует отчёт автоматически, но первый успешный реальный ответ ещё надо проверить.
4. Проверить PR, подтвердить merge отдельно. После разрешённого merge проверить GitHub Actions и опубликованный сайт. До этого frontend не публиковался. Для полноты промышленной платформы ещё нужны доступный файл USGS/устойчивый официальный endpoint и лицензированный источник текущих региональных цен; бесплатные открытые данные их не заменяют.
