# SMM Market Data — приватный кабинет

## Права и способ получения

Проверено 18.11.2026: [условия SMM](https://www.metal.com/compliance-center/terms-and-conditions) требуют разрешения на копирование, загрузку, отображение и использование данных. Общее исключение для личного автоматического сбора не подтверждено. Наличие single-user subscription не означает разрешение на scraping или размещение в сторонней базе.

Разрешённый технический путь автоматизации — [официальный SMM Database API](https://www.metal.com/smm-api). Есть и [официальный Data-pro MCP](https://events.metal.com/ai-stack/docs/smm-datapro-mcp-guide-zh.html): выдаваемый SMM ключ и подписочные права на соответствующие данные. Документация MCP указывает до 20 одновременных вызовов; это не подтверждение бесплатного доступа к любым рядам. Бесплатная лицензия для нашего аккаунта, API-ключ, конкретные ряды и право хранения не предоставлены. Никакая подписка не оформлялась. Автоматический SMM collector/Cron не включён; обхода ограничений нет.

Реализован **импорт пользователем законно полученных данных при наличии права их хранить и использовать**. Подтверждение прав в интерфейсе не создаёт лицензию: его должен обеспечить владелец. Можно использовать разрешённую SMM выгрузку, преобразовав её в документированный JSON. Нельзя импортировать данные только потому, что они видны на странице.

## Использование

1. Открыть `https://alfammetal.ru/#smm`, войти существующим аккаунтом владельца. Только один явно предоставленный Auth user_id включён в закрытый список доступа; другие зарегистрированные пользователи доступа не получают.
2. Если письмо ведёт на localhost: в **Supabase Authentication → URL Configuration** Site URL должен быть `https://alfammetal.ru`, а Redirect URLs должен включать `https://alfammetal.ru/`. Клиент запрашивает возврат `https://alfammetal.ru/#smm`. Это настройка Auth, не DNS. Если шаблон письма содержит OTP-код, поддержан вход по коду. Не пересылать коды/ссылки/токены.
3. Подготовить JSON-массив по `/smm-import-format.json`; до 500 строк и 1 МБ. В формате нет демонстрационных цен.
4. Подтвердить законность получения и право личного хранения, выбрать файл. Импорт атомарный; повтор обновляет те же series/date/currency/unit/tax_status, без размножения записей. Это ручное исправление одной оценки, не архив всех ревизий.

Обязательные поля: series_id, metal_id, specification, purity, delivery_form, region, price_type, assessed_at, date_precision, currency, unit, tax_status, vat_rate, minimum, maximum, mean, source_url. Неизвестная чистота явно записывается как `not stated`; цена такого продукта не приравнивается к известной чистоте. Дату со временем передавать с часовым поясом. Дата без времени не превращается в точное время оценки. Валюты USD/CNY и единицы сохраняются без автоматического FX/VAT пересчёта.

Минимум и максимум передаются вместе; средняя только опубликованная, иначе null. Для одиночной цены minimum/maximum=null, mean=цена. tax_status: included/excluded/unknown; vat_rate — подтверждённая доля, иначе null. Нельзя угадывать 13% по отношению двух USD-значений. Варианты НДС/валют одной series/date группируются в одной карточке; спецификация/регион/форма/тип одного series_id должны быть неизменными. Для другого сорта, концентрата, сплава, премии или фьючерса — отдельная серия с соответствующим price_type. `mtu` не конвертируется в kg металла.

## Безопасность и тесты

Приватная таблица имеет RLS: owner_id = auth.uid() **и** наличие аккаунта в закрытом analytics_internal.smm_owner_access. Самоназначение владельца запрещено. Даже другой вошедший пользователь не может читать, импортировать, менять или удалять данные. Привилегии anon отсутствуют. Allowlist изменяет только администратор в указанном проекте; email/UUID владельца не включаются в публичный репозиторий.

Публичная главная не запрашивает приватные данные. После входа владельца главная читает тот же защищённый набор, что и кабинет. Выход очищает данные в памяти. Нет общих module/localStorage caches, публичного CSV, передачи данных в Groq, смешивания с World Bank или supplier feeds. Учётные токены Supabase Auth обрабатывает стандартный клиент; ключей SMM в frontend нет.

Изолированные SQL-тесты проверяют owner/other/anon, запрет самоназначения, дублей, неверного диапазона и смешения спецификаций. Browser-тесты используют явно тестовую сессию/данные только на localhost: импорт после подтверждения прав, две VAT-формы в одной карточке, мобильный экран, главная и выход. Это **не реальный SMM API-тест** и не вход владельца в production.

## Честный статус покрытия

Структура/импорт поддерживают 13 metal_id, но **реально подключено через SMM: 0 из 13**, пока нет разрешённой выгрузки/API и соответствующих прав. Тестовый пример меди из задания не загружается в production. Для получения настоящих актуальных диапазонов требуется разрешённая выгрузка SMM или официальный доступ с правом личного хранения. После этого можно выполнить реальный импорт и проверить данные под сессией владельца; пароль и токены разработчику не нужны.
