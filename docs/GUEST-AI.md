# Гостевой ИИ-чат — опубликован 16 ноября 2026

Причина изменения: почтовый magic-link перенаправляет на localhost:3000. Владелец выбрал доступ без регистрации. Новый интерфейс не отправляет письма и не требует email/пользовательского JWT. Настройки Auth redirect, DNS, Cloudflare и чужие проекты не меняются. Старые почтовые ссылки не исправляются этой веткой и больше не нужны для чата.

## Серверная защита бесплатного Groq

- GROQ_API_KEY остаётся только в Supabase Secrets. Клиент получает публичный ключ Supabase, временную проверку и ответ, не Groq/service-role ключи.
- Пять гостевых обращений в сутки с одной сети, пауза не менее 30 секунд. Счётчики атомарны в Postgres, день определяется по UTC. Общая сеть может делить квоту. Из forwarded IP сохраняется только HMAC; forwarded-заголовки — ограниченный сигнал справедливого распределения, а не удостоверение личности.
- Сохраняется общий бюджет: по умолчанию до 20 модельных попыток в сутки (настройка AI_FREE_REQUESTS_PER_DAY, жёсткий максимум 40), до четырёх в минуту. Каждый fallback резервируется отдельно. Существующий лимит 160000 токенов и резервация 16000 дополнительно ограничивают число попыток примерно десятью за сутки. Это существенно ниже опубликованной суточной бесплатной квоты Groq; приложение не повышает тариф и не включает биллинг. Другие приложения того же аккаунта могут расходовать его квоту независимо.
- Перед гостевым запросом ai-challenge подписывает проверку для конкретного тела запроса на пять минут. Браузер решает небольшую SHA-256 задачу (16 бит, ограничена временем). Сервер проверяет подпись, срок, тело и результат до доступа к рыночным данным/модели. Одноразовый nonce расходуется атомарно вместе с гостевой квотой; повторное использование отклоняется. Есть скрытое поле-ловушка для простого form-spam.
- Это дополнительное препятствие для дешёвого автоматического спама, не CAPTCHA и не обещание полной защиты от ботов/DDoS. Ключевая защита Groq — общий серверный бюджет; IP и proof-of-work его не заменяют.
- Сохраняются кеш по вопросу/переписке/периоду/данным/провайдеру и блокировка одинаковой работы. Гостевые отчёты в закрытой guest_ai_cache, не в публичном market_ai_reports. Срок кеша сутки. Личный кеш вошедших пользователей сохранён; функция по-прежнему проверяет переданный JWT и отклоняет недействительный. UI использует гостевой маршрут.
- RLS не отключается. Новые счётчики и nonce — в analytics_internal; кеш закрыт от anon/authenticated. RPC гостевой квоты доступен только service_role. Существующие таблицы и данные не удаляются/не открываются.
- Пользователь получает русские сообщения о дневной квоте/паузе, общем бюджете, проверке защиты и недоступности провайдера. Ошибка не выдаётся за ответ модели.

## Проверка опубликованной версии

После разрешённого merge PR #3 и успешного Deploy первый настоящий анонимный вопрос о меди получил HTTP 200 от Groq и отобразился без email. Повтор выявил ложный 403. Подпись проверки отвязана от сетевого маршрута: она по-прежнему защищает тело запроса, срок и одноразовый nonce; сетевой HMAC применяется к квоте текущего запроса, не к проверке права использовать challenge. Это учитывает смену прокси/мобильного адреса. Для сетевого счётчика берётся первый forwarded-адрес, а не последний прокси. Допущен небольшой запас при проверке срока для расхождения часов серверов. Общие бюджеты/nonce/счётчики не сбрасываются.
